## 1. 一句话概要（历史：部材名 AI 推荐）

主界面上的绿色按钮 **【AI 分析】** 就是「**部材名 AI 推荐**」：

> 遍历【分类结果】里每个「アッセンブリ図」的 PDF，把该図番里
> **「数据来源 = `CMD分析・アッセンブリ図`」的全部行**交给 AI，
> 让 AI 结合**圈号坐标、零件图文字坐标、部材マスタ（部品 → 部材 对照）**判断
> 「这个番号的部品装在哪个部材上」，
> 结果**只写进「部材名AI推荐」列**，**不覆盖「部材名」、不改其它任何列、不新增行**。

### 1.1 为什么需要这一列

【CMD 分析】第 1 步是「按番号找圈号 → 把圈号所在零件图的全部文字用 `|` 连起来」当部材名，
有三类先天问题：

| # | 问题 | 结果 |
|---|------|------|
| ① | 两个番号（如 1 和 3）离得很近、又落进同一张零件图，代码分不清谁是谁 | 只能两个都挂上 → `鴨居\|上レール` |
| ② | 图上的文字不一定是部材名（`部品ｾｯﾄ` / `取説` / `鬼目ﾅｯﾄ` 是**部品**） | 部材名被写成部品名 |
| ③ | 图纸上根本没写部材名（只写部品名或尺寸） | 部材名为空 → 写库时补成「その他」 |

AI 分析就是来修这三类错的：结果放**推荐列**，由人在【部品信息】画面确认，避免直接改坏「部材名」。

> **旧功能已停用**：早期版本的【AI 分析】是「用 AI 从 `plu_table.txt` 提取整张部品表」
> （`PartAnalysisService.AnalyzeAndSave`），该按钮现在**不再调用**它；
> 现在按钮只做部材名判定（`MemberNameAiAdvisor`）。

## 5. 处理流程

### 5.1 点击后的入口检查（按顺序，任一不通过即返回）

| 顺序 | 检查 | 判定 | 表现 |
|------|------|------|------|
| 1 | 是否正在运行 | `_isRunning == true` | **静默返回**（不弹窗、不写日志） |
| 2 | 有没有分类结果 | `_classifications` 为空 | 弹窗「请先点击【开始分解】，并在【分类结果】页确认分类后再执行 AI 分析。」；状态「尚未分解，无法 AI 分析」 |
| 3 | 分解输出目录 | `_lastOutputDir` 为空或目录不存在 | 弹窗「找不到分解输出目录，请先执行【开始分解】。」+ 路径；状态「找不到分解输出目录」 |
| 4 | 有没有「アッセンブリ図」 | 快照里 `Category == PdfCategory.Assembly` 的数量为 0 | 弹窗「【分类结果】中没有「アッセンブリ図」的 PDF。…」；状态「没有「アッセンブリ図」，无需分析」 |
| 5 | （仅开发调试）单文件模式 | `PartAnalysisService.DebugSingleFileOnly == true` 时只留 `DebugSingleFileName` | 找不到该文件 → 弹窗「【调试模式】只分析「xxx.pdf」…」；状态「【调试模式】未找到 xxx.pdf」 |
| 6 | AI 密钥 | `AiApiOptions.FromConfiguration().IsConfigured == false` | 弹窗列出三种配置方式（【AI 设置】/ `App.config` 的 `AiApiKey` / 环境变量 `MSIF_AI_API_KEY`）+ 读取错误明细；状态「未配置 AI 密钥」 |

检查通过后：**把【分类结果】复制成快照**（后台线程只读快照，分析期间在界面上改分类不会影响本次运行）。

### 5.2 初始化（后台线程里，一次）

| 步骤 | 内容 |
|------|------|
| 1 | `MemberNamePromptStore.Load()` → 提示词（系统提示 + 用户模板），记 `PromptSource`（外部文件 / 内置资源 / 内置默认值） |
| 2 | `MemberPartCatalogLoader.LoadFor(输出目录)` → 部材マスタ（先读 `MSIF_MemberParts.db` 的「部材部品」表；表里没有数据时才导入一次 `部材部品\部材部品.csv`） |
| 3 | 打开部品基本信息库（`<PDF 文件夹>\AiAppData\MSIF_Parts.db`） |
| 4 | 取目标：`PartAnalysisService.SelectAssemblyTargets(快照)`（分类 = アッセンブリ図） |
| 5 | 写日志：判定范围、提示语来源、部材マスタ（路径 + 部材名/部品名 件数，或不可用警告）、数据库路径、提示词加载错误 |

### 5.3 逐図番（每个「アッセンブリ図」PDF）

| 情况 | 处理 |
|------|------|
| 図番（PDF 文件名去扩展名）解析不出来 | 日志「跳过：无法从 PDF 文件名解析出図番」，不中断 |
| 该図番在库里**没有任何** `数据来源 = CMD分析・アッセンブリ図` 的行 | 日志「（図番）：没有「数据来源 = … 」的行，无需 AI 分析」，**不调 AI** |
| 有这个来源的行 | 记「需要判定 N 行（部材名 空 a 行 / その他 b 行 / 含 `\|` c 行 / 单个名字 d 行）」，进入逐页处理 |
| 处理中抛异常（接口错误、DB 错误等） | 该図番标记失败、`FailedDrawingCount++`，日志「（図番）：AI 分析失败（原因）」，**其它図番继续** |

> 「部材名」是空 / 已经是「その他」/ 单个名字 / 含 `|` 的行**全部都要判**，
> 不再只挑含 `|` 的行（早期版本只判含 `|` 的）。

### 5.4 逐页（同一図番内按「页码」分组，每页一份 `parts_info.json`）

| 情况 | 处理 |
|------|------|
| `页码 <= 0` | 当作第 1 页 |
| 该页读不到 `parts_info.json`（或解析失败） | 跳过该页全部行；日志「第 N 页：读不到 parts_info.json，跳过 X 行（可重新执行【开始分解】生成）（路径/原因）」 |
| 该页行里的番号在 `callouts` 里**一个圈号都找不到** | 跳过该页全部行；日志「第 N 页：番号在 parts_info.json 里找不到圈号（callouts），跳过 X 行」 |
| 正常 | 拼提示词 → **调一次 AI** → 解析答案 → 逐行应用 |

`parts_info.json` 的查找顺序（与【CMD 分析】共用同一份数据）：

1. 「来源PDF」列所在目录：`<PDF 文件夹>\AiAppData\<図番>[_P<页码>]\parts_info.json`；
2. 分解输出根目录：`<输出根>\<図番>[_P<页码>]\parts_info.json`；
3. 都不存在时在上述两个根里按目录名（不区分大小写）找 `<図番>` / `<図番>_P<页码>`。

> 第 1 页目录是 `<図番>\`，第 2 页起是 `<図番>_P2\`、`<図番>_P3\`…

### 5.5 调 AI（每页 1 次）

`ChatCompletionClient.Complete(系统提示词, 用户提示词)`：

| 项 | 值 |
|----|----|
| 协议 | OpenAI 兼容 `POST {BaseUrl}/chat/completions`（`Authorization: Bearer <ApiKey>`） |
| 超时 | `AiTimeoutSeconds`（默认 **180 秒**） |
| 自动重试 | **最多 3 次**，仅对「超时 / 网络错误 / 429 / 5xx」，间隔 2s、4s |
| 其它错误（4xx 等） | 不重试，直接抛出 → 该図番失败 |
| 调用计数 | `AiCallCount++` 只统计**成功完成**的页（重试不另计） |

### 5.6 应用答案（`ApplyResponse`）

1. 解析 AI 回应的 JSON（`{"1":"上ﾚｰﾙ","5":"その他"}`；也容忍包一层数组的写法）；
2. 逐行（同一番号的多行各自处理）按第 7 节的**兜底链**得到最终值；
3. 有值 → 写进内存对象的 `MemberNameAiSuggestion`，日志「第 N 页 番号 X：旧值 → 新值」；
4. 全页处理完后，把该図番有变化的行**一次性**写库：
   `UPDATE 部品基本信息 SET 部材名AI推荐 = ? WHERE 図番 = ? AND 页码 = ? AND 番号 = ? AND 部品コード = ?`
   （单事务；日志「（図番）：已写入「部材名AI推荐」X 行」）。

## 6. 送给 AI 的提示词结构

提示词文件 `Prompts\MemberNameAdvisor.Prompt.txt`，用 `[system]` / `[user]` 分节，
第一个分节之前的 `#` 注释行**不送给 AI**。用户模板里的占位符由程序替换：

| 占位符 | 内容 | 上限 / 说明 |
|--------|------|-------------|
| `{{DRAWING_NO}}` | 図番 | — |
| `{{PAGE}}` | 页码 | — |
| `{{MEMBER_TABLE}}` | 部材マスタ：可回答的部材名 一览 + 每个部材下属的部品名 | 每个部材最多列 **16** 个部品名，超出用「…」 |
| `{{CALLOUT_TABLE}}` | 圈号（番号）坐标表：番号 / 零件图 index / x / y / 是否本次要判定 | 最多 **120** 行 |
| `{{TEXT_TABLE}}` | 零件图文字坐标表：零件图 index / 文字 / 类别 / x / y（类别 = 部材名候选 / 位置标记 / 其它） | 最多 **240** 行 |
| `{{DISTANCE_TABLE}}` | 程序算好的「番号 → 候选部材名」距离表 + 程序建议分配 | 同一候选名只保留最近一处 |
| `{{TARGET_TABLE}}` | 待判定行：番号 / 现在的部材名 / 图上候选部材名 / 部材マスタ线索 | 同一番号多行只列一次 |

坐标单位是 mm，原点在图面左上角（x 向右、y 向下）。
**只送「待判定番号所在零件图」的数据，但同一张零件图上其它番号的坐标也一起给**，
AI 才能比较远近、判断「哪个番号贴哪个部材名」。

AI 的回答被要求「只输出一个 JSON 对象，key = 番号，value = 部材名或『その他』」。

## 7. 判定与兜底链（最关键的一节）

每一行的推荐值按下面顺序取值，**AI 只是第一顺位，不是唯一顺位**：

| 顺位 | 来源 | 条件 | 日志 |
|------|------|------|------|
| ① | **AI 的答案** | 先过 `MatchCandidate` 白名单：<br>a. 该番号在图纸上的候选文字 → 用**图上的写法**；<br>b. 部材マスタ 的**部材名**（含「その他」）→ 用**マスタ 的写法**（图上可能根本没印）；<br>c. 部材マスタ 的**部品名** → 换成它所属的部材名；<br>d. 都对不上 → **丢弃**（防 AI 编造） | 被丢弃：「第 N 页 番号 X：AI 给出的「…」既不在图上候选里、也不在部材マスタ里，已丢弃」 |
| ② | **坐标距离覆盖 AI**（`PreferNearest`） | 仅当①的答案来自「图上候选」，且程序算出的「最近候选」与它不同、且最近比次近**近 ≥ 10%**（`ConfidentGapRatio`） | 「第 N 页 番号 X：AI 判为「A」，但「B」在坐标上近 34%，按距离判定」 |
| ③ | **程序距离建议**（`BuildDistanceAssignments`） | AI 没给 / 给了但被丢弃：按同一零件图内「圈号 → 候选文字」距离升序分配，**同番号只取第一个、同一处文字只配一个番号** | 「第 N 页 番号 X：AI 未给出，按坐标距离判定 → B」 |
| ④ | **候选唯一** | 该番号图上候选去重后**只有 1 个** → 直接用它 | 无（静默） |
| ⑤ | **部材マスタ 反推现在的部材名** | 现在的部材名本身就是部材名 → 原样；是部品名 → 换成它所属的部材名；マスタ 里没有 → 空 | 「第 N 页 番号 X：AI 未给出，按部材マスタ判定 → 右縦枠」 |
| ⑥ | **跳过** | 以上都不行 → 不写推荐（保留该行旧的推荐值） | 只计入「跳过 N 行」 |

补充规则：

- **文字归一化比较**：NFKC（半角カナ → 全角カナ、全角英数 → 半角）+ 去掉全部空白 + 统一大写。
  所以 CSV 里的 `上ﾚｰﾙ` 与 AI 回的 `上レール`、图上的 `上レール` 都能对上。
- **答案范围**：只能是「该番号图纸候选」或「部材マスタ 的部材名」，否则一律丢弃。
- **判断不出部材**时统一用 `その他`（`PartBasicInfo.MemberNameFallback`）。
- **「その他」也是有效答案**：会写进推荐列（不会因为等于「その他」被当成没判）。
- **同一行多次点击**：每点一次都重新算、重新覆盖推荐列（不是追加历史）。

## 12. 错误处理与健壮性

| 场景 | 表现 |
|------|------|
| 运行中重复点击 | 直接忽略（无提示、无日志） |
| 未分解 / 无分类结果 | 弹窗 + 状态提示，不进入分析 |
| 没有「アッセンブリ図」 | 弹窗 + 状态提示，不进入分析（后台 `AnalyzeAndSave` 也有同样的兜底判断：目标为 0 时只写一条警告日志就返回） |
| 未配置密钥 | 弹窗列出三种配置方式 + 读取错误明细，日志/状态报「未配置 AI 密钥」 |
| `parts_info.json` 缺失 / 损坏 | **只跳过该页**，其它页继续，日志写明原因与路径 |
| 该页番号找不到圈号 | **只跳过该页**（省一次 AI 调用） |
| AI 返回非法 JSON / 不带 JSON | 不整页放弃：日志警告 + 改用「坐标距离 / 候选唯一」兜底 |
| AI 编造候选外的文字 | 该行答案丢弃，走兜底链；日志写明被丢弃的文字 |
| AI 判错但坐标明显更近（≥10%） | 改用距离最近者，日志写明两者与百分比（保证同数据每次结果一致） |
| 接口 401 / 403 / 其它 4xx | 不重试，该図番失败，其它図番继续 |
| 接口 429 / 5xx / 超时 / 网络错误 | 自动重试 3 次（2s、4s），仍失败 → 该図番失败，其它図番继续 |
| 单个図番抛异常 | 记「AI 分析失败（原因）」、`FailedDrawingCount++`，不中断整批 |
| 数据库打不开 / 写库异常 | 该図番失败（`UPDATE` 在单事务里，失败不会写半截） |
| 部材マスタ 不可用 | 警告日志，退化为「只用图纸文字」，仍会跑完 |
| 提示词文件读不到 | 静默回退到内嵌资源 / 内置默认值，日志写明来源（有加载错误时追加警告） |
| 分析期间在界面上改分类 | 本次运行不受影响（用的是开始时的快照） |

## 13. 性能与 AI 调用次数

| 项 | 值 |
|----|----|
| 每页调用次数 | **1 次**（仅当该页至少有 1 个番号能在 `callouts` 里找到圈号） |
| 不调 AI 的情况 | 図番没有待判行 / 该页读不到 `parts_info.json` / 该页番号一个圈号都没有 |
| 一次任务的总次数 | 约等于「各図番的页数」之和（例：12 个図番 × 平均 1.3 页 ≈ 15 次，与日志「调用 AI 15 次」一致） |
| 单次最长耗时 | 超时 180 秒 ×（1 次 + 2 次重试）≈ 最坏 9 分钟/页 |
| 界面响应 | 分析主体在 `Task.Run` 后台线程；主界面不卡，但按钮已禁用防重复 |
| 写库 | 每个図番 1 个事务，行数与「待判定行数」同量级 |
| 内存 | 逐页读 `parts_info.json`，不整批缓存所有 PDF 的坐标 |

## 14. 已知限制与注意事项

1. **只判一种来源**：只处理「数据来源 = `CMD分析・アッセンブリ図`」的行；`CMD分析・要領図` /
   `CMD分析・特注品.json` / `AI分析` / `手工追加` 的行不判（需要时在【部品信息】里手工改）。
2. **不改「部材名」**：推荐列只是建议，最终采用需要人工确认；两个列可能长期不一致。
3. **重跑会覆盖**：每次点击都重新计算并覆盖 `部材名AI推荐`，不保留历史、不做变更记录。
4. **部材マスタ 决定上限**：マスタ 为空 / 不全时，AI 只能从图纸文字里选，
   「图上只写部品名」的情况基本判不出来，效果明显变差。
5. **AI 答案必须在白名单内**：候选外的文字一律丢弃 → 可能出现较多「跳过 N 行」。
6. **提示词有截断**：每页最多送 240 条文字、120 条圈号、每个部材 16 个部品名；
   圈号 / 文字特别多的复杂图可能信息不全。
7. **同番号多行**：待判定表里同一番号只列一次（省 token），但该番号的每一行都会写推荐，
   所以同番号不同 `部品コード` 的行会拿到同一个推荐值。
8. **进度条不逐格推进**：开始归零、结束时有写库就置满，不表示「第几个図番」。
9. **必须联网**：接口整図番失败后没有「完全本地重算」的路径（只有坐标距离 / 候选唯一 / 部材マスタ 兜底）。
10. **`页码 <= 0` 按第 1 页处理**：若某行的页码是 0（数据来自其它工具/手工），可能配到第 1 页的 `parts_info.json`。
11. **分类范围来自本次运行**：处理哪些 PDF 取决于当前【分类结果】（来自 `PdfInfoList.txt`）；
    改了分类需要重新分解 / 刷新后再点。
12. **调试开关**：`PartAnalysisService.DebugSingleFileOnly` / `DebugSingleFileName` 只用于开发自测，正式使用请保持 `false`。
13. **需要先跑【CMD 分析】**：本功能不产生部品行，只填一列；没入库就无从判定。

## 18. 追加机能：特注品记录的数量设定（2026-11-15）

> 这是现在【AI 分析】**唯一**的处理内容。
> （2026-11-16 前另一个批次是「部材名判定」，该机能已删除，本文件第 1 ~ 17 章仅作历史存档。）
> 数量设定失败只写日志，不影响其它步骤。

### 18.1 做什么

对选择的 PDF 文件夹下**文件名第 5 位是 `Z`**（特注品，判定口径 = `CmdSpecialProductRule`）的
Excel（`.xls` / `.xlsx` / `.xlsm`）判断数量，并写到：

| 写入目标 | 具体位置 | 定位方式 |
|----------|----------|----------|
| 部品基本信息表 | 「数量」列（`QuantityColumnName`） | 「来源表格文件 = 该図番的 `AiAppData\<図番>\特注品.csv`」（= 【CMD 分析】第 4 步登录的行） |
| `classify\特注品.json` | 每条明细的「員数」 | `file` 相同的条目 |
| `特注品.csv` | **不写** | 该文件由【CMD 分析】最前面一步重新生成，手改会被覆盖 |

### 18.2 两种典型写法（提示词里写死的判定规则）

| 情形 | 例子 | 结果 |
|------|------|------|
| 文章型 | `I400Z10006.xls` 正文 / 注記 写着「1個追加(同梱)」 | `fileQuantity = 1` → 该文件全部行的「数量」= 1（有「同梱」没写数字也按 1） |
| 表型 | `I400Z10002.xls` 的 sheet1 表格里有 数量 / 員数 / 個数 / 入数 / QTY 列 | 逐条 `items[].員数` → 按 部品コード / 部品名 对上行的「数量」 |

两种都有时**表型优先**；数量只照抄 Excel 原文（全角数字、`A` / `C` / `G` 类型代号都不换算、不合计）。

### 18.3 处理流程（一个文件）

1. `ExcelSheetDumper.Read` → 整表原文（所有工作表 + 行号 + 单元格原文，最多 3 万字符）；
2. 从 `特注品.json` 取该 `file` 的已有条目（品種 / 部品名 / 部品コード）作对照；
3. `ChatCompletionClient.Complete` → 解析 `{"fileQuantity", "source", "reason", "items":[…]}`；
4. `UpdateTzJson`：`fileQuantity` 先写该文件全部条目，逐条 `items` 再覆盖；
5. `UpdateDatabase`：`UpdateQuantityBySourceFile`（整份）→ `UpdateQuantityByPart`（逐条，部品コード OR 部品名）。

### 18.4 安全约定

- 数据库文件不存在（还没做过【CMD 分析】）时**不新建库**，只写 `特注品.json`，日志「数据库还不存在…」；
- 判不到数量 / AI 解析失败：该文件不动任何数据，其它文件继续；
- 只改「数量」与「員数」两处，其它列（部材名 / 部品名 / 备注 / 登录时间…）不动；
- 【CMD 分析】第 4 步现在也会把 `特注品.csv` 的「員数」写进「数量」列，
  所以重跑【CMD 分析】后想保留 AI 判的数量，**再点一次【AI 分析】**即可。

### 18.5 日志长什么样

```text
特注品数量设定：扫描 <PDF 文件夹> 下的 Excel（文件名第 5 位是 Z = 特注品）→ AI 判数量 → 写部品基本信息「数量」列 + 特注品.json 的「員数」
  提示语：外部文件（…\Prompts\SpecialProductQuantityAdvisor.Prompt.txt）
  I400Z10006.xls：整份 1（依据：文章）→ DB 数量 3 行 / 特注品.json 3 条
  I400Z10002.xls：逐条 4 条（依据：表）→ DB 数量 4 行 / 特注品.json 0 条
  特注品数量设定：扫描 6 个 Excel（特注品 2 个），AI 调用 2 次 → 写数据库 7 行 / 特注品.json 的「員数」3 条（整份 1 个 / 逐条 4 条 / 没读到数量 0 个 / 跳过 0 个）
```

数字对不上时先看「提示：」行（`特注品.json` 里没有该文件 / 数据库里没有对应的行 等）。

### 18.6 常见问题

| 现象 | 原因 / 处理 |
|------|-------------|
| 日志「读不到 Excel 文字」 | 该 `.xls` 是扫描图 / 加密文件；把文件另存成 `.xlsx` 再试 |
| 日志「数据库里没有对应的行」 | 该図番还没做过【CMD 分析】第 4 步，或该図番的部品没命中分类依据 |
| 数量写成空 | AI 没在文件里找到数量（提示行会带 AI 的说明） |
| 表型的数量对不上部品 | AI 给的 品種 / 部品名 / 部品コード 与 `特注品.json` 不一致；改提示词让 AI 以「已登记的部品」为准 |
