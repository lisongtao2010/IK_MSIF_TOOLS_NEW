# 把程序交给别人时的检查清单

> 适用：把人已经能跑的 `MSIFAITOOLS` 交给同事（公司内）或公司外的人。
> 相关文档：打包签名 `docs\病毒误报_对策.md`、证书申请 `docs\代码签名_IT申请.md`。

## 0. 三句话结论

1. **打包只用 `Tools\Publish-Signed.ps1`**（或直接双击项目根目录的 `发布.bat`），不要直接把 `bin\Debug` 或 `bin\Release` 压缩发人（里面带 `.pdb`，含源码路径，还会带 `.db`）。
2. **默认会清掉包里的 `AiApiKey`**（`-SecretMode BlankAiKey`）——使用者各自在【AI 设置】填自己的 Key；给公司外还要加 `-SecretMode BlankAll` 把 SQL 密码也清掉。
3. 交付走**内网共享 / U 盘 / 公司分发**，不要用邮件附件或网盘链接（会带 Mark-of-the-Web，必然弹 SmartScreen）。

## 1. 为什么必须用发布脚本（踩过的坑）

`bin\<配置>\MSIFAITOOLS.exe.config` 是 `App.config` 的副本，里面是**开发机的真实配置**：

| 项目 | 开发机上的值 | 直接压缩发人的后果 |
|------|--------------|--------------------|
| `AiApiKey` | 你的云端 AI 密钥（真实一串） | 别人白用你的额度，密钥外泄 |
| `MappingDbPassword` | `dairen1111##`（明文） | 数据库账号随程序外泄 |
| `connectionStrings` | `10.103.126.208` / `.209` 明文密码 | 同上 |

发布脚本因此有三件事是**必须**的：

* 剔除 `*.pdb` / `*.xml` / `*.db` / `*.log`（源码路径 + 本地数据）；
* **配置脱敏**：只改发布目录里的副本，仓库里的 `App.config` 不动；
* 生成「发布信息.txt」（版本、构建时间、签名主体、每个文件的 SHA-256）。

## 2. 打包命令

**最省事的方式：双击项目根目录的 `发布.bat`**（不用敲任何命令，不用记证书指纹）。
它会自动：Release 构建 → 清空包内密钥 → 用本机的自签代码签名证书签名 →
把「信任发布者」材料塞进包 → 打 zip → 生成「误报提交材料」文件夹 → 打开产物目录。

```powershell
# 内部同事（已拿到证书，推荐）
.\Tools\Publish-Signed.ps1 -CertificateThumbprint <证书指纹>

# 内部同事，证书还没下来（只做内部测试，别给公司外）
.\Tools\Publish-Signed.ps1 -SkipSign

# 证书还没下来、但想先有一条内部可信的签名链（自签证书，3 年；边界见 病毒误报_对策.md 4.4 节）
.\Tools\New-SelfSignedCodeSigningCert.ps1
.\Tools\Publish-Signed.ps1 -CertificateThumbprint <自签证书指纹>

# 不想找 IT 出证（内网 CA）时用这条：自签 + 把「信任发布者」材料打进包，
# 接收人跑一次包内的 Install-TrustedPublisher.ps1 就显示发布者（不需要管理员、不需要 IT；
# 边界与限制见 病毒误报_对策.md 4.5 节，只适用于公司内部）
.\Tools\New-SelfSignedCodeSigningCert.ps1
.\Tools\Publish-Signed.ps1 -CertificateThumbprint <自签证书指纹> -IncludeTrustedPublisher

# 给公司外 / 演示 / 培训：连 SQL 密码一起清掉
.\Tools\Publish-Signed.ps1 -CertificateThumbprint <证书指纹> -SecretMode BlankAll

# 只用现有 bin\Release 打包（不重新编译，验证流程时用）
.\Tools\Publish-Signed.ps1 -SkipBuild -SkipSign
```

`-SecretMode` 三档：

| 值 | AiApiKey | SQL 密码 | 适用 |
|----|----------|----------|------|
| `BlankAiKey`（默认） | 清空 | 保留 | 内部同事（DB 连接照旧能用，AI 用自己的 Key） |
| `BlankAll` | 清空 | 清空（`Password=` 全空） | 公司外 / 演示 / 不给内网访问 |
| `Keep` | 保留 | 保留 | 只在本机自用，或完全可信的分发 |

打包后**一定**打开这两处确认：

* `发布信息.txt` 里有一行 `配置脱敏    : AiApiKey 已清空（…）`；
* 包里 `MSIFAITOOLS.exe.config` 的 `AiApiKey` /（`BlankAll` 时）`Password=` 都是空值。

## 2.5 改了代码，怎么重新发版

一共 4 步，全程只有**一次双击**：

1. **升级版本号**（强烈建议每次都升）—— 改 `Properties\AssemblyInfo.cs`：

   ```csharp
   [assembly: AssemblyVersion("1.6.1.0")]      // 程序集版本（给 .NET 用）
   [assembly: AssemblyFileVersion("1.6.1.0")]  // ← 这个才是文件属性里看到的版本，也是 zip 名里的版本
   ```

   不升也能发（zip 名带时间戳，不会覆盖），但「版本号永远不变、文件哈希天天变」的 exe
   更容易被杀毒软件当可疑程序，信誉也累积不起来。

2. **关掉正在运行的 `MSIFAITOOLS.exe`（和 `CadPartSplitter.exe`）** —— 文件被占用时
   MSBuild 覆盖不了 exe，构建会直接失败。

3. **双击项目根目录的 `发布.bat`** —— 重新 Release 构建 → 清空密钥 → 签名 → 打 zip →
   生成误报材料。旧包不会被覆盖（文件名带版本号 + 时间戳）。

4. 把新 zip 放共享盘；`artifacts\publish` 里的旧包顺手删掉（每个约 116 MB，很容易堆满盘）。

### 什么时候需要「彻底重建」

| 改动内容 | 做法 |
|---|---|
| 只改了 `.cs` / 窗体 / 资源 / 提示词 csv | 直接双击 `发布.bat`（增量编译够用） |
| **增删过 NuGet 包 / 改过 csproj 的引用** | 先删掉 `bin\Release` 和 `obj`，再双击 `发布.bat` |

不删的话，已经从 csproj 移除的 dll 会残留在包里（脚本会对 OpenCvSharp 之类的残留打警告，
那 87 MB 既浪费体积也扩大误报面）。

### 重新发版后哈希变了，白名单要重加

每次重新编译，exe 的 SHA-256 一定变（签名里还带时间戳）。所以：

* 信息安全是**按文件哈希**加白 → 把新包的 `_误报提交材料\04_哈希清单.txt` 再发一次；
* 信息安全是**按发布者证书 / 目录**加白 → 不用动，证书不换就不用重加。

## 3. 包里应该有什么（自查表）

| 内容 | 缺失会怎样 |
|------|------------|
| `MSIFAITOOLS.exe`（0.6 MB）+ 依赖 dll（PdfiumViewer / PdfPig / System.Data.SQLite / ExcelDataReader…），合计约 **42 MB** | 起不来 |
| `MSIFAITOOLS.exe.config`（已脱敏） | 全部走内置默认值；AI / DB 要手工配 |
| `CadPartSplitter\CadPartSplitter.exe`（27 个文件，≈243 MB） | 【开始分解】第 1 步直接跳过 |
| `x64\` / `x86\`（`pdfium.dll`、`SQLite.Interop.dll`） | PDF 预览 / SQLite 打不开 |
| `Prompts\*.txt`（4 个） | 回退到内嵌提示语，AI 判定规则不能现场调 |
| `部材部品\部材部品.csv` | 部材マスタ 首次导入没数据源，AI 只能用图纸文字 |
| `部品マスタ\Tbl_部品マスタ.csv` | 【CMD 分析】少一部分主档信息 |
| `hiroidashiData\*.xlsx` | 连不上 DB 时「使い分け自動設定」没有兜底 |
| `发布信息.txt` | 报障 / 提交误报时没 SHA-256 |
| `安装信任_双击我.bat` + `trusted-publisher.cer` + `Install-TrustedPublisher.ps1` + `先装信任_再运行.txt`（`-SelfSigned` 或 `-IncludeTrustedPublisher` 时自动附带） | 自签/内网 CA 证书的场景下，接收人装不了信任，程序永远显示「未知发布者」 |

整包 zip ≈ **116 MB**（主程序 42 MB + 分割程序 243 MB，压缩后）；解压后约 285 MB，硬盘要留够。

## 4. 接收人机器上要满足的条件

| 条件 | 说明 / 不满足时的现象 |
|------|----------------------|
| Windows 10/11 **x64** | 程序固定 x64（`PlatformTarget=x64`）；Win8.1 及更早需另装 .NET Framework 4.8 |
| **.NET Framework 4.8** | Win10 1903+ 自带；没有时装上再双击，否则「应用程序无法启动」 |
| 装在**可写目录**（`D:\Tools\...`、桌面、`%LOCALAPPDATA%`） | 不要放 `C:\Program Files`：没有 `D:\MSIFDB` 时数据库会退回 `<程序目录>\Data\`，那里没写权限就建不了库 |
| 能连 `10.103.126.208:1433` / `10.103.126.209:1433` | 连不上：部材名置换、推荐项、【CMD 分析】第 6 步「使い分け」降级（程序仍能跑完） |
| 系统里有能打开 PDF / Excel 的默认程序 | 点「打开结果」时用系统默认程序 |
| AI：自己的 Key，或本机 `claude` CLI | 都没有 →【AI 分析】弹「未配置 AI 密钥」 |

## 5. 第一次运行会自己生成什么（不用手工建）

| 路径 | 内容 |
|------|------|
| `%APPDATA%\MSIFAITOOLS\ai-settings.json` | 【AI 设置】保存的 Key / 接口 / 模型（**每个使用者各自一份**） |
| `%APPDATA%\MSIFAITOOLS\mapping-db-settings.json` | 【接続①genpin】/【接続②MSIF】保存的连接，密码用 DPAPI 按当前用户加密 |
| `D:\MSIFDB\MSIF_MemberParts.db`（D 盘不可用时 `<程序目录>\Data\MSIF_MemberParts.db`） | 部材部品マスタ + 部材 mapping 本机缓存 |
| `<PDF 文件夹>\AiAppData\MSIF_Parts.db`、`parts_info.json` | 跟着图纸文件夹走，一个项目一份 |

所以卸载/迁移时，**配置和数据都在这几处**，程序目录删掉也不丢（除非把库配到程序目录里）。

## 6. 怎么交付

| 方式 | 结果 |
|------|------|
| 内网共享文件夹（推荐）/ U 盘 / 公司软件分发（Intune・GPO） | 不带「来自 Internet」标记 → 不弹 SmartScreen |
| 邮件附件 / OneDrive・百度网盘链接 / 聊天工具传输 | 带 Mark-of-the-Web → **必弹**「Windows 已保护你的电脑」 |
| 直接发exe（不打包） | 缺 `CadPartSplitter\`、原生库、`Prompts\`、CSV，功能残缺 |

发的时候一并给：

* `<包名>.zip`；
* `发布信息.txt`（含 SHA-256，报障和你提交误报都要用）；
* 一页使用说明（或直接贴第 7 节的表）；
* 你的联系方式 + 一句话「被杀软拦了先别删，告诉我型号和检测名称」。

## 7. 给接收人的小抄（可以直接贴给对方）

| 症状 | 怎么做 |
|------|--------|
| 「Windows 已保护你的电脑」/ SmartScreen | 点「更多信息」→「仍要运行」；同时告诉我（我要提交误报，见 `病毒误报_对策.md` 第 5 章） |
| 显示「未知发布者」/ 属性里签名不可用 | 先双击同一文件夹里的 **`安装信任_双击我.bat`**（一次即可，免管理员），再启动程序 |
| 想撤销上面那次信任 | 双击 `安装信任_双击我.bat` 时加参数 `-Uninstall`；Windows 会弹一次「ルート証明書ストア」确认框，点「はい / 是」 |
| 杀毒软件删掉 / 隔离了 exe | 先还原 + 加排除项（解压目录整个加上），把**厂商名 + 检测名称**发我 |
| 双击没反应 / 「应用程序无法启动」 | 装 .NET Framework 4.8（x64），解压到可写目录再试 |
| 「未配置 AI 密钥」 | 程序里【AI 设置】→ 选「云端 OpenAI 兼容接口」→ 填你自己的 Key（保存到你的 `%APPDATA%`，不影响别人） |
| 日志「部材マスタ 不可用」 | 确认 `D:\MSIFDB` 或 `<程序目录>\Data\` 可写；或把 `MemberPartDatabasePath` 指到一个可写路径 |
| 部材名置换 / 推荐项是空的 | 【接続①genpin】填服务器 / 账号 / 密码（DPAPI 加密保存），确认能连 `10.103.126.208:1433` |
| 保存部品信息时提示「部材 mapping 登录失败」 | 同上，检查【接続②MSIF】`10.103.126.209:1433`；不影响本机保存 |
| 目录里有 `部材部品.csv` 但マスタ还是空 | 删掉 `MSIF_MemberParts.db` 后重开（只在表为空时导入一次） |
| 想改 AI 判定规则 | 改 `Prompts\*.txt`，保存即生效（不用重新编译） |

## 8. 给公司外的人（客户 / 演示 / 培训）额外要做的

1. `-SecretMode BlankAll`：**不要**把内网数据库地址密码、你的 AI Key 带出去。
2. 别带公司数据：`部材部品\部材部品.csv`、`部品マスタ\Tbl_部品マスタ.csv`、`hiroidashiData\` 是公司主档数据，按需删掉（删掉程序仍能跑，只是相应功能降级）。
3. 内网 CA 签的证书在公司外**无效**（对方机器没有你的根证书，照样「未知发布者」）→ 对外要 OV/EV 证书或 Azure Trusted Signing，见 `代码签名_IT申请.md` 第 5～6 章。
4. 图纸 / 部品数据的对外提供按公司规定走审批，工具本身不要夹带真实客户图纸。
5. 先在**一台干净的虚拟机**上解压试跑一次（没有 Office、没装 .NET 4.8 的环境各试一次）。

## 9. 发出去之前最后 60 秒

```powershell
# 1) 包在哪、签名什么状态
Get-Content .\artifacts\publish\<包名>\发布信息.txt -Encoding UTF8 -TotalCount 8

# 2) 包里 exe.config 的密钥是不是空的（应该有 AiApiKey 行、value 为空）
Select-String .\artifacts\publish\<包名>\MSIFAITOOLS.exe.config -Pattern 'AiApiKey|Password='

# 3) 有没有漏网 pdb / db
Get-ChildItem .\artifacts\publish\<包名> -Recurse -Include *.pdb,*.db,*.log | Select-Object FullName

# 4) 签名验证（有证书时；NotSigned 会报错，属正常）
Get-AuthenticodeSignature .\artifacts\publish\<包名>\MSIFAITOOLS.exe | Format-List Status,StatusMessage,SignerCertificate

# 5) 信任材料四个文件是不是都在（自签 / 内网 CA 才有；接收人靠 bat 双击安装）
Get-ChildItem .\artifacts\publish\<包名> | Where-Object Name -match '信任|trusted|Trusted' | Select-Object Name,Length

# 6) 真正解压一遍，确认文件名没乱码（重点看「安装信任_双击我.bat」这个名字）
Expand-Archive .\artifacts\publish\<包名>.zip $env:TEMP\ziptest -Force
Get-ChildItem $env:TEMP\ziptest\<包名> | Select-Object Name
```

六项都对，就可以把 zip 发出去了。发出后把 zip + `发布信息.txt` 归档一份（下次被报毒要按这个 SHA-256 提交）。
