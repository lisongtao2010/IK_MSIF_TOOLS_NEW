# 【CMD 分析】同名部品合并「保留装配图番号」功能说明

> 所属项目：`MSIFAITOOLS`（.NET Framework 4.8 / WinForms / x64）
> 源文件：`Services\CmdPartAnalysisService.cs`（`MergeInstructionWithAssembly`）、
> `Services\PartBasicInfo.cs`（`OverrideNumber`）
> 更新日期：2026-11-20

---

## 1. 一句话概要

【CMD 分析】第 3 步把「部品名相同」的 **要領図 行** 与 **アッセンブリ図 行** 合并时，
以前是「删掉装配图行、只留要領図 行」，装配图那一行的 **番号** 也跟着没了。
现在 **装配图行的「番号」由保留下来的要領図 行接手**（区分 仍照旧取装配图行的），
所以部品基本信息画面上仍然能看到装配图的编号。

```
装配图行：番号 3 / 部品名 縦枠 / 区分 A / 部品コード XXX
要領図 行：番号 21 / 部品名 縦枠 / 区分（空）/ 部品コード XXX

合并后（1 行）：
  番号 3 ← 以前是 21（装配图行的 3 随行一起被删掉）
  部品名 縦枠 / 区分 A（照旧取装配图行的区分）/ 数据来源 CMD分析・要領図
```

---

## 2. 规则

| 项目 | 行为 |
|------|------|
| 触发 | 【CMD 分析】第 3 步「要領図部品追加」（`CollectInstructionParts` → `MergeInstructionWithAssembly`）写库前 |
| 合并条件 | 部品名按 `CmdPartAnalysisService.NormalizePartName` 规整后完全相同（空白 / 全角半角 / 英文大小写不算差异） |
| 「番号」 | 保留下来的要領図 行的番号 = **被删掉的装配图行的番号**（`PartBasicInfo.OverrideNumber`）。装配图行番号 ≤ 0 时保持原值 |
| 「区分」 | 与以前一样：用装配图行的区分覆盖要領図 行（`PartBasicInfo.OverrideFrameKind`） |
| 其它列 | 不变：部品名 / 部材名 / 数量 / 部品コード / 备注 / 数据来源 等都是要領図 行的值 |
| 「页码」 | **不变**：要領図 行仍按第 3 步写入时的页码（`1`）；只有「番号」换成装配图的值 |
| 多条同名装配图行 | 一条明细只有一个「番号」：只有**第一条**装配图行的番号能保留，后面的番号丢弃，日志写「番号 N 未保留（…已保留番号 M）」 |
| 数据库唯一键 | 仍是「図番 + 页码 + 番号 + 部品コード」；番号换成装配图的值后照样唯一（同名装配图行已先删掉） |
| 日志 | `同部品名合并：部品名「…」→ 区分 取装配图 番号 3 的「A」，要領図 番号 21 → 装配图 番号 3（保留装配图的番号）（図番 …）`；紧接着仍是原来的「删除装配图行：番号 3 / …」 |

---

## 3. 实现

| 位置 | 说明 |
|------|------|
| `Services\PartBasicInfo.cs` → `OverrideNumber(int number)` | 第 3 步专用：把「番号」改成指定值（`≤ 0` 时忽略），与 `OverrideFrameKind` 成对使用 |
| `Services\CmdPartAnalysisService.cs` → `MergeInstructionWithAssembly` | 第一次命中同名装配图行时，除了 `OverrideFrameKind` 再调 `OverrideNumber(assembly.Number)`；同一要領図 行对上第 2 条以后的同名装配图行时只记「未保留」日志 |
| `Services\CmdPartAnalysisService.cs` → `CollectInstructionParts`（XML 注释） | 同步写明「区分 / 番号 取装配图行」 |

> 改名 / 新增记录：`CmdPartAnalysisService` 没有新方法，只是在既有的同名合并里多覆盖一个字段；
> `PartBasicInfo` 新增 1 个 `public void OverrideNumber(int)`（命名与 `OverrideFrameKind` 一致）。

## 4. 验证要点

1. 一张装配图（図番 X）先跑第 1 步（装配图部品入库），记下某部品的番号（例：`縦枠` = 番号 3）。
2. 跑第 3 步（要領図部品追加）：日志出现「同部品名合并：… 要領図 番号 21 → 装配图 番号 3（保留装配图的番号）」，
   紧接着「删除装配图行：番号 3 / 部品名「縦枠」…」。
3. 打开部品基本信息画面（図番 X）：
   - 部品「縦枠」只剩 **1 行**（数据来源 = `CMD分析・要領図`）；
   - 「番号」显示 **3**（不是 21）、「区分」显示装配图行的区分；
   - 其它列（部材名 / 部品コード / 备注…）仍是原来要領図 行的值。
4. 再点【保存】或重新打开画面：番号仍是 3（写进了数据库，不是只在画面上改）。
5. 同名部品在装配图上有两条不同番号时：第一条的番号保留，日志里能看到另一条「番号 N 未保留」。
6. 装配图行番号 ≤ 0 的异常数据：不覆盖，要領図 行保持自己的番号（日志写「原番号（装配图行没有有效番号）」）。

---

## 5. 注意 / 限制

1. **单跑第 3 步**（不先跑第 1 步）时，库里已经没有装配图行（上次合并时被删掉了）→ 没有番号可接手，
   要領図 行按原来的「接在最大番号之后」编号。要保留番号请用【CMD 分析】主按钮（第 1 → 第 3 步连着跑）。
2. 「页码」没有跟着换：要領図 行仍写 `1`。装配图本身多页、且同名部品在第 2 页以后时，
   画面上是「页码 1 + 装配图第 2 页的番号」—— 这次只按要求保留「番号」。
3. 已经被以前的【CMD 分析】合并掉的装配图行找不回来了：新规则只对**重新执行**第 1 → 第 3 步后生成的数据生效。
4. 一条明细只能有一个「番号」，所以同名装配图行有多条时只有第一条的番号能保留。
