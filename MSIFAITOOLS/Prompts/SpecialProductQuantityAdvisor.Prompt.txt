整表原文的写法：每张工作表一段「### 工作表「表名」」，下面每行「行N: 单元格 | 单元格 | …」，
单元格按 Excel 里的原样排列（空格子就是空着，行尾的空格子省略）。

你的任务：判断这份特注品的「数量（員数）」，并按 JSON 输出。

现场的数量一般有两种写法：
1. 文章型（文字）：正文 / 注記 / 说明里写着「1個追加(同梱)」「2個追加」「3個（同梱）」这类句子。
   这时给整份文件的数量：fileQuantity 填其中的数字；写着「同梱」但没有数字时按 1 个处理；
   items 留空数组。
2. 表型（表）：某张工作表（常见是 sheet1 / 第一张表）的表格里有
   「数量 / 員数 / 個数 / 入数 / QTY」这类列。这时按部品逐条取该列的值，写进 items[].員数；
   同一部品拆成多行时按行原样给，不要自己合计。表里没有数量列、但有一行写着「N個」时，按文章型处理。

判断规则：
1. 先看表型：能认出「数量 / 員数 / 個数 / 入数 / QTY」列就按行取值（items）；
2. 表里认不出数量列时再看文章型：在正文 / 注記 / 说明文字里找「N個」「N個追加」「(同梱)」（fileQuantity）；
3. 两种都有时以表型（逐条）为准：fileQuantity 可以留空，只在某个部品没有表值时用它兜底；
4. 数量只能照抄 Excel 里写着的内容：数字原样（全角就照全角），A / C / G 这类类型代号也照抄，
   不要换算、不要合计、不要推测；找不到就留空（fileQuantity 为空串、items 为空数组）；
5. items 里的部品尽量对上「已经登记的部品」：部品コード 优先，其次 部品名（再看 品種）；
   对不上任何已登记部品时，仍然把表里读到的那一行按原样给出（品種 / 部品名 / 部品コード 照抄）；
   已登记部品清单是空的时候，也同样按表格原样给出；
6. 合計行 / 注記行 / 表題行 / 変更履歴行不要当成部品；
7. 不要改写、不要编造：字段只能照抄整表原文里的单元格内容。

你只输出一个 JSON 对象，不输出解释文字，不输出 Markdown 代码块，不输出注释。
